# DECISIONS and assumptions

Autonomous build decisions. Each is cheap to reverse; see `docs/adr/` for the structural ones.

1. **Versions**: Django 5.2 LTS, Python 3.12 (containers), Postgres 16, Redis 7, Node 22, Next.js 15 (App Router), Tailwind 3.4 (simple preset sharing with the design system), Celery 5.
2. **Brand**: Patchbeast. No "GTA/Rockstar/Vice City" in brand, domain, logo or site name. The launch anchor is described as "Grand Theft Auto VI on PC" in page *content* only (descriptive use). Its URL slug (`gta-6-pc`) is data, not brand; it can be changed in admin.
3. **No invented facts**: seed data has `date = null`, confidence *Rumour*, requirement rows with empty specs, and sources with placeholder URLs, all `is_placeholder=True`, disabled, and rendered `noindex`. Real feeds must be entered by the owner (RUNBOOK: "Add a source").
4. **Verification**: Confirmed = >= 2 independent registrable domains or a video; Reported = 1 source; Rumour = 0 / unsure. Computed by `content.services.verification`, recomputed when Evidence changes. An official source gets *no* special elevation (kept literal to the brief); editors can add Evidence in admin.
5. **Auto-publish** only facts (release date, patch, requirement) with source URL, LLM confidence >= `AUTO_PUBLISH_THRESHOLD` (0.85) and computed verification >= Reported. Everything else -> review. News articles are *never* auto-published.
6. **LLM**: `claude-haiku-5-5` via env `LLM_MODEL`; prices are env-configurable for the cap (defaults $0.10/$0.50 per MTok). No sampling params are sent (Haiku 5.5 rejects non-default values); `effort=low`; JSON is requested in the prompt and validated with pydantic (not provider-specific structured output) so the port stays provider-agnostic. Without `ANTHROPIC_API_KEY` items skip to the review queue.
7. **Cost accounting** uses `usage` from the response; before each call we reserve an estimated worst-case cost so concurrent workers cannot overshoot the cap by much.
8. **Dedupe**: canonical URL (strip tracking params, fragments, `www.`, trailing slash, lowercase host, sort query) then 64-bit simhash over title+lead tokens, hamming distance <= 3 against the last 30 days of the same game.
9. **Polling**: one beat task per minute dispatches due sources (`next_fetch_at`), per-source interval 5-15 min, exponential backoff up to 6 h, auto-disable after 7 days of continuous failure + alert.
10. **YouTube**: only `playlistItems` (1 unit) on the channel's uploads playlist; `search` (100 units) is never called. A local quota ledger in Redis stops calls at `YOUTUBE_DAILY_QUOTA - margin`. WebSub receiver is supported for push (needs public callback).
11. **Robots/ToS**: for `rss`/`api` sources `robots.txt` is checked (cached 24 h) unless the Source is flagged `official_feed` (a feed intended for machine consumption).
12. **Revalidation** is tag-based + path-based; fires after commit, retried with backoff; failure only alerts, it never blocks publishing.
13. **Hardware checker**: client-side, using a small *editorial tier catalogue* (approximate relative tiers, not benchmarks, clearly caveated). Requirement rows optionally reference catalogue ids (`cpu_ref`, `gpu_ref`); without refs the checker says it cannot compare automatically.
14. **Newsletter**: double opt-in with unguessable random tokens (256-bit, stored server-side), honeypot + throttle, unsubscribe link and `List-Unsubscribe` header, weekly digest idempotent per ISO week.
15. **Monetisation**: AdSlot/HardwareCard exist but render nothing unless the feature flag is on *and* configured; affiliate disclosure always shown with HardwareCard.
16. **Analytics**: Plausible script only when `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` is set; no cookies.
17. **Admin**: Django admin at `/admin/`; review queue at `/admin/review/`. Put it behind a strong password + 2FA at the proxy if you have a static IP (RUNBOOK).
18. **Local verification limits**: the build sandbox had no Docker daemon, so compose files are validated statically (`docker compose config` where possible) and the app is smoke-tested natively against local Postgres/Redis. See README "Known gaps".
19. **Vercel**: optional. `vercel.json` builds only the web app from the monorepo; the API remains on the VPS (ADR 0007).
20. **Vercel**: `/vercel.json` (repo-root project: `npm ci`, `npm run build -w apps/web`, output `apps/web/.next`) and `apps/web/vercel.json` (Root Directory = `apps/web`). The web build never fails when the API is unreachable: the API layer returns a result object, pages degrade, ISR heals within 5 minutes. `BUILD_STANDALONE` (Docker only) must not be set on Vercel.
21. **Near-duplicates from a different outlet** are kept as their own (queued) article *and* recorded as independent Evidence on the original, so a second outlet can raise a fact from Reported to Confirmed; same-outlet near-duplicates are dropped.
22. **Videos** from sources flagged `trusted_channel` auto-publish (a video counts as confirming evidence for itself); all others queue for review.
23. **Legal pages** (privacy/terms/affiliate/contact) are sensible templates, not legal advice: have them reviewed before launch, especially once ads/affiliate go live.
24. **Revalidation tags**: `game:<slug>`, `games`, `ticker`, `sitemap`, `news`, `videos`; the web fetch layer tags each request accordingly.
25. **No Celery result backend** (fire-and-forget tasks, idempotent by design); dead-letter = `AlertingTask.on_failure` alert + stuck-article sweeper, not a separate queue.
26. **Platforms (PC first)**: a game tracks a list of platforms in `hub_config.platforms` (`pc`, `ps5`, `xbox_series`, `switch2`; registry in `modules/common/platforms.py`, PC always first). Each platform has its own current release (own verification + countdown); patches carry a platform (unique per game+platform+version); **requirements and the checker stay PC-only**. Auto-publish only accepts facts for platforms the game tracks; a fact with an unknown platform, or a console requirement, goes to review. The LLM prompt asks for a platform and the schema normalises aliases (`PlayStation 5` -> `ps5`, unknown -> `other`).
27. **Vanity path (flagship pages)**: `Game.vanity_path` (e.g. `gta-6-pc`) makes `/<path>` the canonical hub URL and 308-redirects `/games/<slug>` to it. Config-driven (no game named in code); reserved site paths are rejected; subpages stay under `/games/<slug>/...`. The sitemap lists the vanity path.
28. **"What we know / what we don't"** is derived only from sourced hub data (release per platform, PC requirements, patches, videos), so gaps are shown openly and nothing unsourced is stated. JSON-LD `gamePlatform`/`datePublished` are emitted only for platforms with a Reported/Confirmed date.
29. **Per-game newsletter**: `Subscriber.games` (empty = all). Signing up on a game page narrows to that game (adds to an existing narrow list); the home page sets "all". The digest is built per subscriber and is not sent when none of their games changed.
30. **Per-game SEO copy** (`hub_config.seo_title` / `seo_description`) overrides the generated title/description; the seed's text describes the tracker only and makes no claims about the game.
31. **Upgrading a running deployment**: migrations are additive (`Game.vanity_path`, `Patch.platform` default `pc`, `Subscriber.games`). `make seed` re-applies the placeholder anchor, including its `hub_config` (it overwrites that field for the anchor only).
32. **Game sections, each with its own pages**: Overview (`/<vanity>` or `/games/<slug>`), Patches & updates (`/patches`, with a page per update at `/patches/<platform>/<version>`), News (`/news`), Videos, PC requirements, Timeline (`/timeline`). A tab bar and breadcrumbs (with `BreadcrumbList` JSON-LD) appear on all of them. There is deliberately **no page per news item**: news is a link-out with our short summary, and a page per item would be thin, near-duplicate content.
33. **Patch pages are indexable only with real content**: not a placeholder, at least one linked source, and our summary or highlights. Our highlights are short original paraphrases (max 8) plus the size; never the publisher's text. Verification is computed from the linked sources (2+ independent domains = Confirmed).
34. **Content packs** (`apps/api/content_packs/*.json`, loaded with `manage.py load_pack <name> [--dry-run]`) are the way to add sourced starter content. They go through the normal services (evidence, verification, timeline entries), are idempotent, and are opt-in: nothing real is loaded by `seed`. The bundled `gta6` pack was compiled on 2026-11-24 **from search-result snippets, not the full pages**: it must be verified against the publisher's own pages before you publish. It deliberately contains no PC release date (none is verified).
35. **The stored patch `notes_url` is never labelled "official"**; the detail page lists linked sources and only adds the notes link if it is a new site.
36. **Countdown** shows `Released` once a live date has passed; platform rows show `Released <date>`. The hero stays on the primary platform (PC) because the site is PC-first, so a game that is out on consoles can still show "PC: Date unconfirmed" honestly.
